# DRT 네트워크 시뮬레이션 성능 분석 보고서

## 🔴 주요 성능 병목 지점

### 1. 배정 알고리즘의 중첩 루프 (최대 병목)
**위치**: `drt_network_assignment.py`의 `_find_best_insertion()` 메서드 (177-204줄)

**문제점**:
- 각 차량마다 `(path_len + 1) × (path_len + 2) / 2` 개의 후보 경로를 생성
- 경로 길이가 10이면 약 66개의 후보, 20이면 231개의 후보 생성
- 각 후보마다 `_calculate_path_time()` 호출 → 각 stop마다 최단 경로 계산

**복잡도**: O(n² × m × k)
- n: 경로 길이
- m: 차량 수
- k: 각 경로 계산 비용 (최단 경로 알고리즘)

**예시**: 
- 경로 길이 10, 차량 2대 → 약 132번의 경로 시간 계산
- 각 계산마다 평균 5개 stop → 약 660번의 최단 경로 조회

### 2. build_route_nodes()의 반복적 최단경로 계산
**위치**: `drt_network_simulation.py` 220-233줄

**문제점**:
- 각 요청 처리마다 `previous_path`와 `new_path` 모두에 대해 호출
- 각 stop마다 `nx.shortest_path()` 호출 → 매우 비용이 큰 연산
- 시각화를 위한 것이지만 매 요청마다 실행됨

**영향**:
- 요청 20개, 평균 경로 길이 5 → 약 200번의 최단 경로 계산
- 네트워크 그래프가 크면 각 계산이 수백 ms 소요 가능

### 3. 시각화 단계의 추가 경로 계산
**위치**: `drt_network_simulation.py` 359-371줄

**문제점**:
- 각 이벤트마다 차량의 현재 위치에서 시작 위치까지의 중간 경로 계산
- 이벤트가 많을수록 계산량 증가

### 4. NetworkX 최단 경로 알고리즘의 오버헤드
**위치**: `drt_network_assignment.py` 101줄, `drt_network_simulation.py` 225줄, 362줄

**문제점**:
- `nx.shortest_path()` 및 `nx.shortest_path_length()`는 그래프 크기에 따라 비용이 큼
- 큰 네트워크에서는 각 호출이 수십~수백 ms 소요 가능
- 캐싱이 있지만 첫 호출 시 비용이 큼

## 📊 예상 성능 영향

### 현재 설정 (NUM_DEMANDS = 20, NUM_VEHICLES = 2)
1. **배정 단계**: 
   - 요청 20개 × 차량 2대 × 평균 후보 50개 × 경로 계산
   - 예상: 수천~수만 번의 최단 경로 조회

2. **경로 구축 단계**:
   - 요청 20개 × 2개 경로(previous/new) × 평균 5 stop
   - 예상: 약 200번의 최단 경로 계산

3. **시각화 단계**:
   - 이벤트 수 × 중간 경로 계산
   - 예상: 추가 수십~수백 번의 계산

**총 예상 시간**: 네트워크 크기에 따라 수 분~수십 분 소요 가능

## ✅ 개선 방안

### 우선순위 1: build_route_nodes() 지연 실행
- 시각화 단계에서만 실행하도록 변경
- 배정 단계에서는 경로 노드 구축 생략

### 우선순위 2: 경로 계산 최적화
- `_calculate_path_time()`에서 증분 계산 활용
- 불필요한 경로 계산 제거 (조기 종료 조건 추가)

### 우선순위 3: 사전 계산 및 캐싱 강화
- 자주 사용되는 노드 쌍에 대한 경로 사전 계산
- 더 큰 캐시 크기 설정

### 우선순위 4: 알고리즘 최적화
- 경로 길이 제한
- 휴리스틱을 통한 후보 수 감소
