# 성능 저하 원인 분석: 20개부터 느려지는 이유

## 🔴 핵심 문제: O(n²) 복잡도의 중첩 루프

### 현재 알고리즘의 복잡도 분석

`_find_best_insertion()` 메서드 (drt_network_assignment.py 165-205줄):

```python
path_len = len(vehicle.path)  # 경로 길이 = n

for pickup_index in range(path_len + 1):  # n+1 번 반복
    for dropoff_index in range(pickup_index + 1, len(path_with_pickup) + 1):  # 평균 (n+2)/2 번 반복
        new_path_time = self._calculate_path_time(...)  # 경로 길이 m에 대해 m번의 최단 경로 조회
```

**복잡도**: O(n² × m)
- n: 현재 경로 길이 (stop 개수)
- m: 후보 경로의 평균 길이
- 각 후보마다 경로 시간 계산 필요

### 경로 길이 증가 패턴

요청이 많아질수록 차량의 경로가 길어집니다:

| 요청 수 | 평균 경로 길이 (stop) | 후보 수 (n²/2) | 계산량 증가 |
|---------|---------------------|---------------|------------|
| 5개     | 2-5                 | 3-15          | 1x         |
| 10개    | 5-10                | 15-66         | 4x         |
| 20개    | 10-20               | 66-231        | 15x        |
| 30개    | 15-30               | 120-496       | 33x        |

### 실제 계산량 추정

**10개 요청 시:**
- 경로 길이: 평균 7 stop
- 후보 수: 약 28개
- 차량 2대: 56개 후보
- 각 후보 경로 계산: 평균 7 stop → 7번의 최단 경로 조회
- 총 계산: 약 392번의 최단 경로 조회

**20개 요청 시:**
- 경로 길이: 평균 15 stop
- 후보 수: 약 120개
- 차량 2대: 240개 후보
- 각 후보 경로 계산: 평균 15 stop → 15번의 최단 경로 조회
- 총 계산: 약 3,600번의 최단 경로 조회

**계산량 증가: 3,600 / 392 ≈ 9.2배**

### 추가 요인

1. **캐싱 효과 감소**: 경로가 길어질수록 새로운 노드 쌍이 많아져 캐시 히트율 감소
2. **메모리 사용 증가**: 경로 복사 및 후보 생성 시 메모리 사용량 증가
3. **가비지 컬렉션**: 많은 임시 객체 생성으로 GC 오버헤드 증가

## ✅ 해결 방안

### 1. 조기 종료 (Early Termination)
현재 최적해보다 나쁜 후보는 즉시 건너뛰기

### 2. 경로 길이 제한
일정 길이 이상의 경로는 배제하거나 휴리스틱 사용

### 3. 휴리스틱 기반 후보 필터링
모든 후보를 검사하지 않고 유망한 후보만 선택

### 4. 증분 계산 (Incremental Calculation)
전체 경로를 다시 계산하지 않고 증가분만 계산
