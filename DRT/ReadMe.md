# 실시간 수요응답형 교통(DRT) 배차 시뮬레이터 (개선 버전)

본 프로젝트는 실시간으로 발생하는 승객의 요청에 따라 DRT(Demand-Responsive Transit) 차량의 최적 경로를 탐색하고 배차하는 과정을 시뮬레이션합니다. 이전 버전의 단점을 보완하여 **성능, 배차 효율성, 현실성**을 크게 개선했으며, 전체 운행 과정을 텍스트 로그와 애니메이션으로 시각화합니다.

-----

## ✨ 주요 개선 사항 (Key Features)

이 시뮬레이터는 초기 모델에서 다음과 같은 핵심적인 발전을 이루었습니다.

1.  **성능 개선 (Performance Improvement)**

      * 모든 경로 조합을 탐색하던 기존의 완전 탐색($O(N^2)$) 방식에서, 출발지와 목적지를 순차적으로 최적 위치에 삽입하는 **휴리스틱(Heuristic) 방식($O(N)$)으로 변경**하여 연산 속도를 획기적으로 향상했습니다.

2.  **업무 쏠림 현상 완화 (Workload Balancing)**

      * 단순히 '거리 증가량'만 보던 비용 함수를 개선하여, **'총 업무량(예상 경로 길이)'을 함께 고려하는 다중 목표 비용 함수**를 도입했습니다. 이를 통해 특정 차량에만 배차가 몰리는 현상을 억제하고 차량들을 더 균등하게 활용합니다.

3.  **현실적인 버스 모델 구현 (Realistic Bus Model)**

      * 차량에 **최대 탑승 인원(Capacity)** 제약을 추가했습니다. 배차 시, 경로의 어느 지점에서도 탑승객 수가 용량을 초과하지 않는지 검사하여 '합승 택시'가 아닌 **'버스/셔틀'** 모델에 가깝게 수정했습니다.

-----

## 🧠 핵심 로직: 휴리스틱 기반 다중 목표 비용 알고리즘

본 시뮬레이터는 \*\*'순차적 최선 삽입 휴리스틱(Best Sequential Insertion Heuristic)'\*\*과 \*\*'다중 목표 비용 함수(Multi-Objective Cost Function)'\*\*를 결합한 알고리즘을 사용합니다.

신규 승객 요청이 발생했을 때의 배차 결정 과정은 다음과 같습니다.

1.  **차량 순회**: 운행 중인 모든 차량에 대해 아래 과정을 수행하여 비용을 계산합니다.
2.  **휴리스틱 경로 탐색**:
      * **1단계 (출발지 삽입)**: 신규 승객의 \*\*출발지(P)\*\*를 현재 차량의 경로에 삽입했을 때, 경로 증가량이 가장 적은 최적의 위치 `i`를 찾습니다.
      * **2단계 (목적지 삽입)**: 1단계에서 찾은 위치 `i`는 고정한 채로, 그 이후 위치들 중에서 \*\*목적지(D)\*\*를 삽입했을 때 경로 증가량이 가장 적은 최적의 위치 `j`를 찾습니다.
3.  **제약 조건 검사 (Constraint Check)**:
      * 2단계에서 임시 경로가 만들어질 때마다, 해당 경로의 모든 지점에서 **차량의 최대 용량(`VEHICLE_CAPACITY`)을 초과하지 않는지 검사**합니다. 만약 용량을 초과하는 경로라면, 즉시 후보에서 제외합니다.
4.  **다중 목표 비용 계산**:
      * 유효한 최적 후보 경로가 정해지면, 최종 비용을 아래의 가중치 공식으로 계산합니다.
      * **`최종 비용 = (w1 * 거리 증가량) + (w2 * 배차 후 총 경로 길이)`**
          * **거리 증가량**: 순수한 운행 효율성을 나타냅니다. (가중치: `W_COST_INCREASE`)
          * **총 경로 길이**: 차량의 미래 업무 부담량을 나타냅니다. 이 값이 클수록 페널티를 주어 업무 쏠림을 방지합니다. (가중치: `W_PATH_LENGTH`)
5.  **최종 배차 결정**: 모든 차량에 대해 계산된 **'최종 비용'이 가장 낮은 차량**에게 신규 승객을 최종 배정합니다.

## 📖 주요 용어 정의

시뮬레이션을 정확히 이해하기 위해 다음 용어의 차이를 알아두는 것이 중요합니다.

  * **배차된 승객 (Assigned Passengers)**
      * 시스템이 승객의 요청을 접수하여 특정 차량의 **'할 일 목록(`path`)'에 추가한 상태**를 의미합니다. 차량은 이 승객을 태우러 갈 *예정*입니다.
  * **탑승 중인 승객 (Onboard Passengers)**

## 🧠 핵심 로직: 최소 삽입 비용 탐색 (Minimum Insertion Cost)

이 시뮬레이터의 배차 결정 알고리즘은 **'최소 삽입 비용(Minimum Insertion Cost)'을 찾는 완전 탐색(Brute-force) 기반의 휴리스틱 알고리즘**을 사용합니다.

신규 승객 요청(출발지 P, 목적지 D)이 발생했을 때의 처리 과정은 다음과 같습니다.

1.  **모든 차량 검토**: 운행 중인 모든 차량을 순회합니다.
2.  **모든 경우의 수 계산**: 각 차량의 현재 남은 경로(`path`)에 P와 D를 삽입할 수 있는 모든 위치 조합(`i`, `j`)을 생성합니다.
3.  **비용 계산**: 각각의 조합에 대해, 경로의 총 이동 거리가 기존보다 얼마나 증가하는지(`cost_increase`)를 계산합니다. 이 **거리 증가량**이 바로 '비용'이 됩니다.
4.  **최적해 선택**: 모든 차량, 모든 조합 중에서 **비용(`cost_increase`)이 가장 적은 단 하나의 경우**를 최적해로 선택합니다.
5.  **경로 업데이트**: 선택된 차량의 경로를 최적해의 경로로 즉시 업데이트합니다.

이 방식은 각 배차 결정 순간에 가장 효율적인(이동 거리 증가가 가장 적은) 선택을 하는 \*\*탐욕 알고리즘(Greedy Algorithm)\*\*의 일종입니다.

  * **업무 쏠림 현상 (Workload Imbalance)**:
      * **원인**: 알고리즘이 \*\*오직 '거리 효율성'\*\*이라는 단일 기준으로만 판단하기 때문에 발생합니다.
      * **과정**: 이미 바쁘게 운행 중인 차량은 새로운 요청을 기존 경로 사이에 끼워 넣는 비용이 저렴한 반면, 멀리서 대기 중인 차량은 요청지로 이동하는 비용이 커서 계속 선택받지 못합니다.
      * **결과**: 이로 인해 **한 차량에만 계속해서 업무가 몰리고, 다른 차량은 계속 대기**하게 되는 '부익부 빈익빈' 현상이 발생하여 시스템 전체의 효율성과 공평성을 저해할 수 있습니다.
  * **전역 최적해 미보장**: 매 순간의 선택이 지역적으로는 최적일지라도, 그 선택들이 모여 전체 시뮬레이션 기간 동안의 글로벌 최적해(Global Optimum)를 보장하지는 않습니다.


# (이전코드) DRT_V1

## 📄 개요

본 프로젝트는 **수요응답형 대중교통(DRT, Demand-Responsive Transport)** 시스템의 핵심 기능인 **라우팅 알고리즘**을 Python으로 구현한 시뮬레이터입니다.

새로운 승객의 탑승 요청이 발생했을 때, 여러 대의 차량 중 어떤 차량이, 어떤 경로로 해당 승객을 서비스하는 것이 가장 효율적인지를 결정하는 과정을 시뮬레이션합니다. '방향'과 '거리'를 모두 고려하여 최적의 차량을 배정하는 로직을 직관적으로 이해할 수 있도록 돕는 것을 목표로 합니다.

## 🧠 적용 알고리즘

이 코드는 **최소 추가 비용 삽입 휴리스틱 (Lowest Cost Insertion Heuristic)** 알고리즘을 기반으로 합니다.

알고리즘의 작동 방식은 다음과 같습니다.

1.  **신규 요청 접수**: 새로운 승객의 출발지와 목적지 정보를 받습니다.
2.  **모든 경우의 수 탐색**: 현재 운행 중인 모든 차량의 기존 경로에 대해, 신규 승객의 `출발지(Pickup)`와 `목적지(Drop-off)`를 삽입할 수 있는 모든 가능한 위치 조합을 탐색합니다.
3.  **비용 계산**: 각 조합에 대한 총 경로 길이를 계산하고, 기존 경로와의 차이, 즉 \*\*'추가 비용(추가 거리)'\*\*을 도출합니다.
4.  **최적 해 선택**: 계산된 '추가 비용'이 가장 적은 차량과 경로를 최종적으로 선택하고, 승객을 배정합니다.

이 방식은 신규 승객의 이동 방향과 비슷한 경로로 운행 중인 차량에게 더 낮은 '추가 비용'을 부여하므로, 자연스럽게 가장 효율적인 차량에 배정하게 됩니다.

## ⚙️ 코드 구성

  - **`Point` 클래스**:
      - 각 지점(승객 출발지, 목적지 등)의 ID와 좌표(x, y)를 저장합니다.
  - **`Vehicle` 클래스**:
      - 차량의 고유 ID와 현재 경로(`path`) 정보를 가집니다.
      - `path`는 `Point` 객체들의 순서 있는 리스트로, 차량의 경유지 순서를 의미합니다.
  - **`calculate_distance(p1, p2)` 함수**:
      - 두 `Point` 객체 간의 유클리드 거리를 계산합니다.
  - **`calculate_path_distance(path)` 함수**:
      - 주어진 경로(`path`)의 총 이동 거리를 계산합니다.
  - **`assign_passenger_to_vehicle(...)` 함수**:
      - **핵심 로직이 담긴 함수**입니다.
      - 동적 차량 경로 문제(Dynamic Vehicle Routing Problem) 해결을 위한 삽입 휴리스틱(Insertion Heuristic) 알고리즘을 사용한 것입니다. 조금 더 구체적으로는 최소 추가 비용 삽입(Lowest Cost Insertion) 또는 탐욕적 삽입(Greedy Insertion) 방식이라고 부를 수 있습니다.
      - 신규 승객 정보를 받아 모든 차량의 모든 경로 조합을 테스트하여, 최소 추가 비용이 발생하는 최적의 차량과 새로운 경로를 반환합니다.

## 📊 시뮬레이션 예제 분석

코드 내 예제 시나리오는 다음과 같습니다.

1.  **초기 상태**:
      - `차량 1`: 승객 `P1`을 태우고 `(1, 1)`에서 `(5, 5)`로 이동 중입니다.
      - `차량 2`: 승객 `P2`를 태우고 `(10, 10)`에서 `(15, 12)`로 이동 중입니다.
2.  **신규 요청**:
      - 새로운 승객 `NewP`가 `(2, 2)`에서 `(6, 6)`으로 가는 요청을 합니다.
3.  **알고리즘 실행**:
      - **`차량 1`에 `NewP`를 태우는 경우**: 기존 경로와 방향이 유사하여 추가되는 거리가 상대적으로 적습니다.
      - **`차량 2`에 `NewP`를 태우는 경우**: 완전히 다른 방향으로 운행 중이므로, `NewP`를 태우고 내리기 위해 돌아가는 거리가 매우 길어져 추가 비용이 크게 발생합니다.

      - 알고리즘은 **'최소 추가 비용' 원칙**에 따라 `NewP`를 **`차량 1`에 배정**합니다.
