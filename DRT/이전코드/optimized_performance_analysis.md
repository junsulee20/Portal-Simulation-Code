# Optimized 파일 성능 분석 보고서

## 📊 현재 최적화 상태

### 이미 적용된 최적화
1. ✅ 경로 노드 구축 지연 실행 (시각화 단계로 이동)
2. ✅ 경로 길이 제한 (MAX_PATH_LENGTH = 18)
3. ✅ 후보 수 제한 (MAX_CANDIDATES_TO_EVALUATE = 80)
4. ✅ 조기 종료 (EARLY_TERMINATION_THRESHOLD = 1.3)
5. ✅ 증분 계산 (경로가 길 때)
6. ✅ 적응형 계산 (경로가 짧으면 전체 계산)

## 🔴 여전히 남아있는 성능 병목 지점

### 1. 배정 알고리즘의 O(n²) 복잡도 (가장 큰 병목)

**위치**: `drt_network_assignment_optimized.py`의 `_find_best_insertion()` 메서드

**문제점**:
```python
for pickup_index in range(path_len + 1):  # n+1 번
    for dropoff_index in range(pickup_index + 1, len(path_with_pickup) + 1):  # 평균 n/2 번
        new_path_time = self._calculate_path_time(...)  # 각 후보마다 경로 계산
```

**현재 제한**:
- MAX_CANDIDATES_TO_EVALUATE = 80으로 제한
- 하지만 경로가 짧을 때는 여전히 많은 후보를 평가

**계산량 예시 (20개 요청)**:
- 경로 길이: 평균 15 stop
- 이론적 후보 수: (15+1) × (15+2) / 2 = 136개
- 제한 적용: min(136, 80) = 80개
- 차량 2대: 160개 후보
- 각 후보마다 경로 계산: 평균 15 stop → 15번의 최단 경로 조회
- 총 계산: 약 2,400번의 최단 경로 조회

**개선 여지**:
- 후보 수 제한을 더 엄격하게 (80 → 50)
- 휴리스틱 기반 후보 필터링 (유망한 후보만 선택)

### 2. 통행시간 계산의 반복 호출

**위치**: `drt_network_simulation_optimized.py`의 `calculate_path_travel_time()` 함수

**문제점**:
```python
def calculate_path_travel_time(...):
    for stop in path:
        travel = travel_time_cache.travel_seconds(current_node, stop.node_id)
        # 각 stop마다 최단 경로 조회
```

**영향**:
- 각 요청마다 경로의 모든 stop에 대해 최단 경로 조회
- 경로가 길수록 조회 횟수 증가
- 요청 20개, 평균 경로 길이 15 → 약 300번의 추가 최단 경로 조회

**개선 방안**:
- 배정 단계에서 이미 계산된 경로 시간을 재사용
- 통행시간 계산을 배정 단계와 통합

### 3. 증분 계산의 오버헤드

**위치**: `drt_network_assignment_optimized.py`의 `_calculate_path_time_incremental()`

**문제점**:
- 증분 계산이 복잡하고 여러 번의 최단 경로 조회가 필요
- 경로가 짧을 때(≤5)는 전체 계산이 더 빠르지만, 경로가 길 때 증분 계산도 비용이 큼
- 각 삽입 지점마다 경로를 다시 계산

**개선 방안**:
- 증분 계산 최적화 (더 효율적인 알고리즘)
- 경로 시간 캐싱 강화

### 4. NetworkX 최단 경로 알고리즘의 오버헤드

**위치**: `NetworkTravelTimeCache.travel_seconds()`

**문제점**:
- `nx.shortest_path_length()`는 그래프 크기에 따라 비용이 큼
- 첫 호출 시 캐시 미스로 인한 지연
- 큰 네트워크에서는 각 호출이 수십~수백 ms 소요 가능

**현재 캐싱**:
- Dict 기반 캐싱으로 중복 계산 방지
- 하지만 첫 호출 시 비용이 큼

**개선 방안**:
- 사전 계산 (자주 사용되는 노드 쌍)
- 더 효율적인 최단 경로 알고리즘 사용 (A* 등)

### 5. 경로 복사 오버헤드

**위치**: `_find_best_insertion()` 메서드

**문제점**:
```python
path_with_pickup = vehicle.clone_path()  # 경로 복사
path_candidate = list(path_with_pickup)  # 또 복사
```

**영향**:
- 각 후보마다 경로 리스트 복사
- 후보 80개 × 차량 2대 = 160번의 복사
- 경로가 길수록 복사 비용 증가

**개선 방안**:
- 불변 데이터 구조 사용
- 경로 복사 최소화

### 6. 시각화 단계의 경로 계산

**위치**: `drt_network_simulation_optimized.py`의 `plot_final_assignment()`

**문제점**:
- 시각화 시에만 경로 노드를 계산하지만, 여전히 많은 최단 경로 계산 필요
- 각 이벤트마다 중간 경로 계산

**영향**:
- 요청 20개 → 약 20번의 경로 노드 구축
- 각 구축마다 여러 최단 경로 계산

**개선 방안**:
- 시각화 최적화 (필요한 경로만 계산)
- 경로 계산 결과 캐싱

## 📈 성능 예측 (20개 요청 기준)

### 현재 최적화 적용 후 예상 계산량

1. **배정 단계**:
   - 요청 20개 × 차량 2대 × 후보 80개 × 경로 계산
   - 각 경로 계산: 평균 15 stop → 15번의 최단 경로 조회
   - 총: 약 2,400 × 15 = 36,000번의 최단 경로 조회

2. **통행시간 계산**:
   - 요청 20개 × 평균 경로 길이 15 stop
   - 총: 약 300번의 최단 경로 조회

3. **시각화 단계**:
   - 이벤트 20개 × 경로 노드 구축
   - 총: 약 200-400번의 최단 경로 계산

**총 예상**: 약 36,500-36,700번의 최단 경로 조회

### 최적화 전 대비

- 최적화 전: 약 3,600 × 15 = 54,000번 (후보 제한 없음)
- 최적화 후: 약 36,000번
- **개선율: 약 33%**

## ✅ 추가 개선 방안

### 우선순위 1: 후보 수 제한 강화
- MAX_CANDIDATES_TO_EVALUATE: 80 → 50
- 휴리스틱 기반 후보 필터링 추가

### 우선순위 2: 경로 시간 재사용
- 배정 단계에서 계산한 경로 시간을 통행시간 계산에 재사용
- 중복 계산 제거

### 우선순위 3: 증분 계산 최적화
- 더 효율적인 증분 계산 알고리즘
- 경로 시간 부분 캐싱

### 우선순위 4: 사전 계산
- 자주 사용되는 노드 쌍에 대한 경로 사전 계산
- 네트워크 그래프 분석 후 핵심 경로 미리 계산

### 우선순위 5: 알고리즘 개선
- 휴리스틱 기반 후보 선택 (모든 후보를 평가하지 않고 유망한 후보만)
- 경로 길이 제한을 더 엄격하게 (18 → 15)

## 🎯 결론

현재 optimized 파일들은 이미 상당한 최적화가 적용되어 있지만, 여전히 O(n²) 복잡도의 배정 알고리즘이 주요 병목입니다. 

**20개 요청 기준으로는 여전히 수만 번의 최단 경로 조회가 필요**하며, 네트워크 그래프가 크면 각 조회가 수십~수백 ms 소요될 수 있어 전체 실행 시간이 길어질 수 있습니다.

추가 최적화를 통해 **50-70% 추가 성능 향상**이 가능할 것으로 예상됩니다.
